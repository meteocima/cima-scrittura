# Materiali di prova

File finti, costruiti apposta per le prove. Nessun contenuto reale: nessun
progetto, partner, persona o risultato di CIMA.

| File | Che cos'è | Che cosa deve far emergere |
|---|---|---|
| `lettera-ministero.docx` | lettera istituzionale con anti-pattern messi apposta | apertura vuota ("Certamente!"), "unicamente posizionato", "a 360 gradi", "da un lato, dall'altro", chiusure di rito |
| `template-deliverable.docx` | template di deliverable con sezioni e segnaposto | la struttura va rispettata, anche l'allegato su dati e codice che nessuno ricorda |
| `deliverable-bozza.docx` | bozza di deliverable scritta male | risultati dichiarati e non dimostrati, KPI senza baseline, "nessuno scostamento" falso, allegato mancante |
| `review-report.pdf` | review report con quattro commenti e due raccomandazioni | va letto come PDF, e ogni commento deve finire nella tabella della risposta |

Per la prova sulla traduzione di un mazzo non c'è un file qui: si usa il
mazzo prodotto dalla prova 10, che è il caso vero (si traduce quello che si è
appena fatto) e evita di tenere in repository una seconda copia del template.

I primi tre nascono da HTML convertiti con LibreOffice, quindi la loro
impaginazione è povera: va bene, le prove guardano il contenuto e il formato
di consegna, non la grafica.
